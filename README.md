# edu

مستودع مشروع **edu** — منصة Nexus Agent. تطبيق Express مع واجهة ثابتة، جلسات دردشة، وتنفيذ وكلاء عبر مزودي LLM (OpenAI وxAI وأي مزود متوافق مع OpenAI) مع بث النتائج عبر SSE. اختبارات الوحدة والتكامل مدمجة في Node، واختبارات المتصفح عبر Playwright. واجهة OAuth المذكورة مسار تجريبي فقط ولا تنفذ تسجيل دخول حقيقيًا.

## البدء

يتطلب Node.js **22.13 أو أحدث** (يُنصح بـ Node 24 LTS)، لأن قاعدة البيانات تعتمد على الوحدة المدمجة `node:sqlite` بدون أي اعتماديات أصلية.

```bash
npm ci
npm start
```

افتح `http://localhost:3000`، أو اختبر حالة الخدمة على `http://localhost:3000/api/health`. لتغيير المنفذ، اضبط المتغير `PORT`.

يستخدم الخادم `helmet`، وتحديد حجم JSON إلى `100kb`، ومحدد معدل للطلبات على مسارات `/api`. تُنشأ قاعدة بيانات SQLite تلقائيًا في `data/nexus.sqlite` وتُطبق ملفات الترحيل عند الإقلاع.

## تهيئة مزود LLM

تُقرأ المتغيرات التالية عند الإقلاع وتُتحقق منها صحة قيمها (وحدة `server/config.js`):

| المتغير | الوصف |
| --- | --- |
| `LLM_PROVIDER` | `openai` أو `xai` أو `openai-compatible` (الافتراضي `openai`) |
| `LLM_API_KEY` | مفتاح المزود — مطلوب |
| `LLM_MODEL` | اسم النموذج — مطلوب |
| `LLM_BASE_URL` | عنوان أساسي مخصص؛ مطلوب مع `openai-compatible` فقط |
| `LLM_TIMEOUT_MS` | مهلة الطلب بالمللي ثانية (الافتراضي 60000) |
| `LLM_TEMPERATURE` | اختيارى بين 0 و2 |
| `LLM_MAX_TOKENS` | اختياري، عدد صحيح موجب |

عند غياب التهيئة يظل الخادم يعمل ويستجيب `/api/health`، لكن مسارات التنفيذ ترجع `503` مع قائمة أخطاء التحقق. راجع [.env.production.example](.env.production.example) كمثال.

## واجهة برمجة التطبيقات

المصادقة الحالية مؤقتة: أي قيمة غير فارغة في ترويسة `X-API-Key` تُعد هوية مالك (تُخزن كتجزئة SHA-256 فقط)، إلى حين تنفيذ المصادقة الحقيقية.

- `POST /api/sessions` — إنشاء جلسة (`{ "title": "..." }` اختياري).
- `GET /api/sessions` — جلسات المالك الحالي.
- `GET /api/sessions/:sessionId` — تفاصيل الجلسة وتنفيذاتها؛ `403` لغير المالك.
- `POST /api/sessions/:sessionId/runs` — تنفيذ جديد بجسم `{ "prompt": "..." }`. الاستجابة بث SSE بأحداث `run.started` ثم `run.delta` لكل جزء من الإجابة ثم حدث نهائي واحد: `run.completed` أو `run.failed` أو `run.aborted` أو `run.timeout`.
- `GET /api/runs/:runId` — سجل التنفيذ (الحالة، المخرجات، الاستهلاك، المدة).
- `POST /api/runs/:runId/abort` — إيقاف تنفيذ جارٍ؛ يرجع `409` إن كان قد انتهى.

الإلغاء والمهلات: انقطاع اتصال العميل يلغي التنفيذ تلقائيًا، وتجاوز `LLM_TIMEOUT_MS` ينهيه بحالة `timeout`.

## الفحوصات

```bash
python3 scripts/check_repo.py
npm test                 # اختبارات الوحدة والتكامل (مشغّل الاختبارات المدمج في Node)
npm run test:e2e:install
npm run test:e2e
```

تشمل اختبارات التكامل محاكاة استجابات المزود عبر اعتراض `fetch` (تدفق ناجح، أخطاء HTTP، إلغاء، ومهلة)، وفحص ملكية الجلسات والتنفيذات عبر HTTP، ومسار الترحيل والمستودعات على قاعدة بيانات في الذاكرة.

تعمل الفحوصات والاختبارات تلقائيًا في GitHub Actions عند فتح Pull Request أو الدفع إلى `main`. يحدث Dependabot اعتماديات npm وGitHub Actions أسبوعيًا.

راجع [دليل إعداد GitHub](GITHUB_SETUP.md) للخطوات الاختيارية في إعدادات المستودع والاستفادة من الخطة المجانية.
